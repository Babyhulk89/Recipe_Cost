# Tests

## Test 1 - Generate after selecting multiple options [sanity]
Viewport: desktop
Covers: POST /api/generate, multi-option recipe builder, structured recipe recovery
Description: Verifies RecipeCost generates a usable recipe from combined selections.
Steps:
1. Choose Cuisine = Creole, Main food = Shrimp, Gluten free, two flavor preferences, and several food-group ingredients
2. Generate a recipe
3. Wait for the result
Expected: RecipeCost returns a usable structured recipe and does not expose a raw 500 error.

## Test 2 - Generate with broad food taxonomy selections
Viewport: desktop
Covers: expanded food taxonomy, coherent-subset selection, POST /api/generate
Description: Verifies broad food selections still produce a coherent dish.
Steps:
1. Select six to ten foods/categories from different food groups
2. Choose a specific cultural cuisine
3. Generate a recipe
Expected: The result uses a coherent subset appropriate to the cuisine and restrictions.

## Test 3 - Generate with saved dietary and allergen profile
Viewport: mobile
Covers: saved dietary profile, allergen hard constraints, POST /api/generate
Description: Verifies saved restrictions remain active.
Steps:
1. Sign in and load a saved Gluten free + Dairy free profile with a Peanut allergy
2. Select a cuisine and main food
3. Generate a recipe
Expected: A usable recipe is produced while all saved restrictions remain enforced.

## Test 4 - Generate BBQ and large-event recipes
Viewport: desktop
Covers: BBQ controls, meal prep, large serving support, POST /api/generate

1. Choose St. Louis BBQ, low-and-slow smoking, Hickory and Dry rub
2. Set a large serving count
3. Generate
Expected: RecipeCost returns practical BBQ guidance and scaling notes.

## Test 5 - Generation fallback remains usable
Viewport: desktop
Covers: /api/generate, /api/generate-fallback, frontend recovery
Description: Verifies a transient advanced-generation failure still returns a usable recipe.
Steps:
1. Trigger a recipe generation request
2. Allow recovery to run if advanced generation fails
Expected: A usable recipe appears without a raw status-code error or alarming fallback copy.

## Test 6 - Private access gate and account creation
Viewport: desktop
Covers: private app gate, owner/invite access, sign-in, backend restriction

Steps:

2. Confirm only Private Access is visible
3. Open an authorized invite or owner link and sign in
Expected: Only authorized signed-in accounts can enter the application.
